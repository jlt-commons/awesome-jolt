# Contributing

Thanks for taking the time to contribute.

## Guidelines

- Check that your suggestion isn't already listed.
- One pull request per project. Small, focused PRs are easier to review than one PR bundling several additions.
- Search open and closed pull requests before submitting, to avoid a duplicate.
- Follow the existing entry format:

  ```markdown
  - [Name](link) - Description.
  ```

  The description starts with a capital letter and ends with a period. Keep it to one or two sentences: what the project does, not why it's good.
- Put the entry in the most specific category that fits. If none fits, propose a new one in your PR description and say why.
- The project should be actively usable today: a real README, and something a reader could actually run or depend on. Placeholder or empty repositories don't qualify yet.
- Alphabetical order within a category isn't enforced here (several sections are already grouped by what a project does rather than its name), but don't reorder unrelated entries as part of an unrelated change.

## Adding yourself or your project

If you maintain a Jolt project and want it listed, open a pull request the same way. Say a sentence about maintenance status if it isn't obvious from the README (actively developed, looking for maintainers, and so on).

## Removing an entry

Projects get removed if they're archived, deleted, or replaced by something better. Say which and why in the PR description.

## Code of conduct

Discussion here follows the [jlt-commons Code of Conduct](https://github.com/jlt-commons/.github/blob/main/CODE_OF_CONDUCT.md), shared across the organization.
